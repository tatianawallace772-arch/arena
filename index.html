    How Nano Banana Studio works

    A thin, honest client over a public keyless endpoint. No backend, no telemetry, no account.

    The pipeline

    1. You write a prompt. Style presets and “exclude” text are folded into the final string locally.
    2. We build a GET URL to image.pollinations.ai/prompt/… with model, size, seed and flags baked into the query.
    3. A pacer spaces requests so the free tier does not 429 a batch of four.
    4. The bytes land as a Blob when CORS allows; otherwise we fall back to a plain <img> load.
    5. Only URLs + settings are stored, in localStorage — the same prompt and seed always reproduce the image.

    Limits of a keyless tier

    • ≈ 1 request every 15 seconds per network. Batch and variations queue themselves.
    • Free output can carry a provider watermark; nologo is best-effort.
    • Nano Banana models are sometimes gated to registered tiers — the app detects that and falls back to a model that answers, then tells you which one served.
    • No uptime promise. Use the offline mock renderer if you need a dependable demo.
